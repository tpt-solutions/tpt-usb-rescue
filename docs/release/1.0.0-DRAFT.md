# tpt-usb-rescue 1.0.0 — release notes (DRAFT, not published)

> Status: draft. Do not publish until the hardware checks below pass. The version in `Cargo.toml` is
> still 0.1.0.

## Release gate (must pass before publishing)

- [ ] Image a healthy USB stick at full speed on Windows and on Linux. Record the throughput.
- [ ] Image a stick with real bad sectors without the OS hanging. Check that stalled reads time out
      and the run continues.
- [ ] Linux: confirm the USB re-enumeration reset recovers a device that stops responding (needs root).
- [ ] Unplug a device mid-run, then resume with `--resume`. Confirm no sector is marked recovered
      that is not on disk.
- [ ] Carve a real-world image and check the intact count against a reference tool.
- [ ] `cargo deny check`, `cargo test --workspace`, MSRV 1.85 check, and CI all green on `main`.

## Highlights

- Read-only, direct-I/O imaging with three passes (sweep, sector retry, edge trimming), a
  crash-safe binary mapfile, resume, and ddrescue/TOML export.
- Stalled reads time out after 5 s. On Linux the USB device is re-enumerated (needs root).
- Signature carver for 20 file types, with structural end detection and validators. Validation
  rejects false positives below a 0.5 score.
- FAT32, exFAT and NTFS parsers that work without the partition table, including deleted entries.
- BLAKE3 and SHA-256 digests, and `verify` against the source image.
- Windows GUI (`tpt-usb-rescue-gui`) built on the Win32 API, with no third-party dependencies.
- macOS raw-disk backend (type-checked, not run on hardware).

## Safety

- The source device is always opened read-only.
- Output on the source disk, and imaging the system disk, are refused unless explicitly overridden.
- Dependencies are checked with `cargo deny`: a crate is accepted when one of its licenses is
  permissive and listed. Crates offered only under Apache-2.0 are rejected.

## Known limitations

- Not yet run against failing hardware. The hardware paths are compiled and tested on synthetic
  data only.
- The carver is contiguous only. Fragmented files are not reassembled.
- JPEG validation checks segment structure, not entropy-coded data. Header-only formats are scored
  on their structure fields only.
- No reset on Windows or macOS.
- Filesystems other than FAT32, exFAT and NTFS are not read.

## Upgrade notes

First release. No upgrade path from 0.x is needed, but the mapfile format (`TPTMAP01`) is fixed for
1.x: a mapfile written by 1.0.0 must remain readable by later 1.x releases.
